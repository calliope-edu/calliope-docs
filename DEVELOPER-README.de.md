## 🎯 Projekt-Philosophie

Dieses Projekt nutzt SvelteKit für **maximale Trennung von Content und Code**. Content-Editoren arbeiten hauptsächlich in `/src/content/` mit Markdown-Dateien und lokalen Assets, während Entwickler die Anwendungsinfrastruktur pflegen. Das System bewahrt die volle Svelte-Funktionalität, sodass beide Rollen Hand in Hand arbeiten können.

## 📁 Projektstruktur

```
calliope-docs/
├── src/
│   ├── content/              # 📝 Content-Dateien (Markdown + Assets)
│   │   ├── python/           # Content-Kategorie
│   │   ├── tech/             # Weitere Kategorie
│   │   └── */
│   ├── routes/               # 🛣️ SvelteKit-Routing
│   │   ├── [...slugs]/       # Catch-all-Route für Content
│   │   ├── [...slugs].json/  # JSON-API für Content
│   │   └── sitemap.xml/      # Sitemap-Generierung
│   ├── lib/
│   │   ├── components/       # Svelte-Komponenten
│   │   ├── mdsvex/           # MDsveX-Custom-Komponenten
│   │   ├── templates/        # Seiten-Layout-Templates
│   │   ├── scripts/          # Core-Loading-Logik
│   │   └── paraglide/        # i18n (Paraglide)

```

## 🏗️ Kern-Architektur

### 1. Content Management System

#### Content-Dateistruktur

Content liegt in `/src/content/`, organisiert nach Kategorien:

```
src/content/
├── python/
│   ├── index.page                           # Kategorie-Landingpage
│   ├── [...01]module/                       # Geordneter Unterordner
│   │   └── index.page
│   ├── [...02]beschleunigungsmesser/       # Weiterer Unterordner
│   │   ├── index.page                       # Standard (German Fallback)
│   │   ├── index.de.page                    # Deutsche Version (optional)
│   │   ├── index.en.page                    # Englische Version (optional)
│   │   ├── image.png                        # Lokalisierte Assets
│   │   └── demo.mp4
│   └── ...
└── tech/
    └── ...
```

**Wichtige Konventionen:**

- **Datei-Endungen**: `.page`, `.de.page`, `.en.page`, `.svx`, `.md`
- **Ordering-Prefix**: `[...01]`, `[...02]`, etc. für Ordner-Sortierung (wird aus URLs entfernt)
- **Exclusion-Prefix**: `!`-Prefix (z.B. `!index.page`) schließt von Navigation/Sitemap aus
- **Index-Dateien**: `index.page` dient als Kategorie/Ordner-Landingpage
- **Sprach-Dateien**: 
  - `index.page` = Fallback-Version (typischerweise Deutsch)
  - `index.de.page` = Deutsch-spezifisch
  - `index.en.page` = Englisch-spezifisch
- **Assets**: Bilder, Videos, PDFs können neben Content-Dateien platziert werden

#### Frontmatter-Schema

Jede `.page`-Datei beginnt mit YAML-Frontmatter:

```yaml
---
title: Seitentitel                # Erforderlich: Seitentitel
description: SEO-Beschreibung     # Optional: Meta-Beschreibung
template: docs                    # Optional: Template(s) (kommagetrennt für Verschachtelung)
published: true                   # Optional: Veröffentlichungsstatus (false = ausgeschlossen)
docMenu: python                   # Optional: Welches Doc-Menü anzeigen
docTitle: Abschnittstitel         # Optional: Doc-Abschnittstitel
seotitle: Custom SEO Title        # Optional: Title für SEO überschreiben
tags: tag1, tag2                  # Optional: Kommagetrennte Tags
image: ./thumbnail.jpg            # Optional: Hero/Thumbnail-Bild
---

# Seiteninhalt in Markdown
```

### 2. Routing-System

#### Dynamischer Route-Handler

Die Hauptroute ist eine **Catch-all-Route**: `/src/routes/[...slugs]/+page.js`

```javascript
// Lädt Content basierend auf URL-Slug
import { loadPage } from '$lib/scripts/pageLoader';

export async function load({ params, depends }) {
   depends("paraglide:lang");
   return await loadPage({ params });
}
```

**Funktionsweise:**

1. **Glob-Import**: Nutzt Vites `import.meta.glob()`, um ALLE `.page`-Dateien zur Build-Zeit zu importieren
2. **Sprach-Auflösung**: 
   - Erkennt Sprache aus URL (`/en/...`) oder Browser-Einstellungen
   - Fallback auf Standardsprache (Deutsch)
   - Sucht nach sprachspezifischer Datei (`.de.page`, `.en.page`)
   - Fallback auf Standard-Datei (`.page`)
3. **Slug-Matching**: Matched URL-Pfad zu Dateipfad nach Entfernen der Ordering-Prefixes
4. **Rückgabe**: `{ Page, meta }` - Die Svelte-Komponente und ihre Metadaten

**Page Loader** (`/src/lib/scripts/pageLoader.js`):

```javascript
const allFiles = import.meta.glob(
    '$lib/../{content/**/,content}{[!!][!index]*,*/index}{,.??}.page',
    { eager: true }
);
```

Dieses Pattern:
- Matched alle `.page`-Dateien in content
- Schließt Dateien aus, die mit `!` beginnen
- Inkludiert `index`-Dateien und Nicht-Index-Dateien
- Unterstützt Sprach-Suffixe (`.de`, `.en`)

### 3. MDsveX Processing Pipeline

MDsveX konvertiert Markdown zu Svelte-Komponenten mit Custom-Processing.

#### Eigene MDsveX-Plugins (`/mdsvexplugins/`)

**1. `mdsvex-relative-images.js`**

Transformiert relative Bild-Referenzen in Markdown zu Vite-kompatiblen Imports:

```markdown
![Alt-Text](./image.jpg|w=800)
```

Wird zu:

```javascript
import img_abc123 from './image.jpg?w=800&enhanced';
```

**Features:**
- Bildoptimierungs-Parameter (`w=`, `h=` für Breite/Höhe)
- Wildcard-Imports: `./images/*.jpg` importiert alle passenden Bilder
- EXIF-Metadaten-Extraktion (Titel, Beschreibung, Copyright)
- Automatische Vite imagetools-Integration
- PhotoSwipe-Galerie-Support

**2. `mdsvex-import-components.js`**

Injiziert automatisch Komponenten-Imports in jede Markdown-Datei:

```javascript
import Svg from '$lib/components/elements/Svg.svelte';
import GitLink from '$lib/components/elements/GitLink.svelte';
import Admonition from '$lib/components/elements/Admonition.svelte';
// ... und mehr
```

**Nutzung in Markdown:**

```markdown
<Admonition type='tip'>
Das ist ein Tipp!
</Admonition>

<Video src="./demo.mp4" />
```

**Verfügbare Komponenten:**
- Layout: `Gap`, `Grid`, `Box`, `Divider`, `Zigzag`
- Media: `Svg`, `Video`, `ImageSwiper`, `YouTube`, `Vimeo`
- Docs: `Admonition`, `Steps`, `Step`, `TabbedLinks`, `UnfoldItem`
- Utility: `Button`, `GitLink`, `VersionNav`, `Versions`
- Highlighting: `V` (highlight), `Yes`, `No`

**3. `mdsvex-frontmatter-to-import.js`**

Importiert Bilder, die im Frontmatter referenziert werden:

```yaml
---
image: ./thumbnail.jpg
---
```

Wird zu:

```javascript
import thumbnail from "./thumbnail.jpg?jpeg&w=520";
metadata.image = thumbnail;
```

**4. `mdsvex-import-templates.js`**

Ersetzt Template-Stub mit tatsächlichen Imports:

```javascript
let availTemplatesArray = {}
```

Wird zu:

```javascript
import Blog from '$lib/templates/__layout-blog.svelte';
import Default from '$lib/templates/__layout-default.svelte';
// ...
let availTemplatesArray = { blog: Blog, default: Default, ... }
```

### 4. Pre-Build-System

Zwei kritische Scripts laufen vor jedem Build:

#### 1. Pack Static Folder (`prebuild/packStaticFolder/index.cjs`)

**Zweck**: Assets aus Content-Ordnern in Static-Output mit korrekter Struktur kopieren.

**Prozess**:
1. Scannt `/src/content/` nach Media-Dateien (Bilder, Videos, PDFs, etc.)
2. Scannt `/static/` nach allen Dateien
3. Entfernt Ordering-Prefixes (`[...01]` → leerer String)
4. Kopiert nach `/static_autogenerated/` mit bereinigten Pfaden
5. Dupliziert in sprachspezifische Ordner (`/en/`, `/de/`)

**Warum?**: Assets neben Content-Dateien müssen zur Laufzeit verfügbar sein, und SvelteKit serviert nur aus `/static`. Dieses Script überbrückt die Lücke.

**Beispiel**:
```
src/content/python/[...02]beschleunigungsmesser/image.jpg
    → static_autogenerated/python/beschleunigungsmesser/image.jpg
    → static_autogenerated/de/python/beschleunigungsmesser/image.jpg
    → static_autogenerated/en/python/beschleunigungsmesser/image.jpg
```

#### 2. Generate Sitemap (`prebuild/generate-subpage-files.cjs`)

**Zweck**: Eine Navigations-/Sitemap-Struktur aus Content-Dateien vorbauen.

**Prozess**:
1. Scannt alle `.page`-Dateien in `/src/content/`
2. Liest Frontmatter-Metadaten
3. Baut hierarchische Struktur nach Content-Typ und Sprache
4. Generiert `/src/sitemap.js` mit Hilfsfunktionen

**Output-Struktur** (`src/sitemap.js`):

```javascript
const sitemap = {
  "de": {
    "python": {
      mainCategories: [...],  // Top-Level-Kategorien
      paths: {                // Alle Pfade mit Metadaten und Unterseiten
        "python/module": {
          slug: "python/module",
          title: "Module",
          description: "...",
          subpages: [...]
        }
      }
    },
    "tech": { ... }
  },
  "en": { ... }
}
```

**Hilfsfunktionen**:
```javascript
getContentTypes(lang)           // ['python', 'tech']
getCategories(contentType, lang) // Haupt-Kategorien
getSubpages(path, lang)         // Unterseiten
getPage(path, lang)             // Einzelne Seiten-Metadaten
```

**Verwendet von**:
- Navigationsmenüs (`DocsMenu.svelte`)
- Breadcrumbs
- Vor/Zurück-Navigation
- Sitemap-Generierung

### 5. Verwendung von Seiten-Metadaten & Navigation

**Eine der mächtigsten Funktionen**: Die vorgenerierten Sitemap ermöglicht automatische Erstellung von Navigation, Menüs und Seitenlisten ohne manuelle Konfiguration.

#### Verfügbare Hilfsfunktionen

Import aus `sitemap.js`:
```javascript
import { getContentTypes, getCategories, getSubpages, getPage } from '$lib/../sitemap.js';
import { getLocale } from "$lib/paraglide/runtime";
```

**Funktionsübersicht**:

```javascript
// Alle Content-Typen für eine Sprache
getContentTypes('de')  // → ['python', 'tech']

// Hauptkategorien eines Content-Typs
getCategories('python', 'de')  
// → [{ slug: 'python/module', title: 'Module', ... }, ...]

// Unterseiten eines beliebigen Pfades
getSubpages('python/module', 'de')  
// → [{ slug: 'python/module/radio', title: 'Radio', description: '...', ... }, ...]

// Einzelne Seiten-Metadaten
getPage('python/module/radio', 'de')  
// → { slug: 'python/module/radio', title: 'Radio', description: '...', ... }
```

#### Beispiel 1: Auto-generiertes Sidebar-Menü

**Anwendungsfall**: Alle Kategorien und ihre Unterseiten in einer Sidebar anzeigen.

```svelte
<script>
  import { getCategories, getSubpages } from '$lib/../sitemap.js';
  import { getLocale } from "$lib/paraglide/runtime";
  
  export let contentType = 'tech';  // oder 'python'
  
  // Alle Hauptkategorien holen
  $: categories = getCategories(contentType, getLocale());
</script>

<nav>
  {#each categories as category}
    <div class="category">
      <h3>{category.title}</h3>
      <ul>
        {#each getSubpages(category.slug, getLocale()) as page}
          <li>
            <a href="/{page.slug}/">{page.title}</a>
          </li>
        {/each}
      </ul>
    </div>
  {/each}
</nav>
```

**Echte Implementierung**: Siehe `src/lib/components/menues/DocsMenu.svelte`

#### Beispiel 2: Content-Übersichtsseite (Karten)

**Anwendungsfall**: Alle Unterseiten als klickbare Karten anzeigen (wie `docs_contents` Layout).

```svelte
<script>
  import { getSubpages } from '$lib/../sitemap.js';
  import { page } from '$app/state';
  import { getLocale } from "$lib/paraglide/runtime";
  
  // Aktuellen Pfad aus URL holen
  $: currentPath = (page?.params?.slugs || '').replace(/\/$/, '');
  
  // Alle Unterseiten automatisch holen
  $: pages = getSubpages(currentPath, getLocale());
</script>

{#if pages && pages.length > 0}
  <div class="cards">
    {#each pages as subpage}
      <a href="/{subpage.slug}/" class="card">
        {#if subpage.image}
          <img src="/{subpage.slug}/{subpage.image}" alt={subpage.title} />
        {/if}
        <h3>{subpage.title}</h3>
        <p>{subpage.description}</p>
      </a>
    {/each}
  </div>
{/if}
```

**Echte Implementierung**: Siehe `src/lib/templates/__layout-docs-contents.svelte`

#### Beispiel 3: Vor/Zurück-Navigation

**Anwendungsfall**: Zwischen Seiten in Reihenfolge navigieren.

```svelte
<script>
  import { getCategories, getSubpages } from '$lib/../sitemap.js';
  import { getLocale } from "$lib/paraglide/runtime";
  
  export let contentType = 'python';
  export let currentSlug = 'python/module/radio';
  
  // Alle Seiten als flache Liste
  $: categories = getCategories(contentType, getLocale());
  $: allPages = categories.flatMap(cat => 
    getSubpages(cat.slug, getLocale())
  );
  
  // Aktuellen Seiten-Index finden
  $: currentIndex = allPages.findIndex(p => p.slug === currentSlug);
  
  // Vor/Zurück berechnen
  $: prevPage = allPages[currentIndex - 1] || null;
  $: nextPage = allPages[currentIndex + 1] || null;
</script>

<nav>
  {#if prevPage}
    <a href="/{prevPage.slug}/">← {prevPage.title}</a>
  {/if}
  {#if nextPage}
    <a href="/{nextPage.slug}/">{nextPage.title} →</a>
  {/if}
</nav>
```

**Echte Implementierung**: Siehe `src/lib/components/menues/DocsMenu.svelte` (berechnet `prev` und `next`)

#### Beispiel 4: Dynamische Breadcrumbs

**Anwendungsfall**: Navigationspfad basierend auf URL-Struktur anzeigen.

```svelte
<script>
  import { getPage } from '$lib/../sitemap.js';
  import { page } from '$app/state';
  import { getLocale } from "$lib/paraglide/runtime";
  
  $: segments = page?.params?.slugs?.split('/').filter(Boolean) || [];
  
  // Breadcrumb-Pfad aufbauen
  $: breadcrumbs = segments.map((_, i) => {
    const path = segments.slice(0, i + 1).join('/');
    return getPage(path, getLocale());
  }).filter(Boolean);
</script>

<nav>
  <a href="/">Home</a>
  {#each breadcrumbs as crumb}
    → <a href="/{crumb.slug}/">{crumb.title}</a>
  {/each}
</nav>
```

#### Verfügbare Metadaten-Felder

Jedes Seiten-Objekt enthält:

```javascript
{
  slug: 'python/module/radio',      // Vollständiger Pfad
  title: 'Radio',                   // Aus Frontmatter
  description: 'Kommunikation...',  // Aus Frontmatter
  image: 'thumbnail.jpg',           // Aus Frontmatter (optional)
  template: 'docs,default',         // Template-Konfiguration
  subpages: [...],                  // Unterseiten (falls vorhanden)
  // ... weitere Frontmatter-Felder
}
```

#### Vorteile

- **Keine Konfiguration**: Navigation aktualisiert sich automatisch beim Hinzufügen von Content
- **DRY-Prinzip**: Seiten-Infos einmal definieren (Frontmatter), überall nutzen
- **Type Safety**: Single Source of Truth für alle Seiten-Metadaten
- **Performance**: Zur Compile-Zeit vorgebaut (kein Runtime-Parsing)
- **Flexibilität**: In jeder Komponente nutzbar, eigene Navigations-Patterns erstellbar

### 6. Template-System

**Mehrschichtiges Template-System** für flexible Layouts.

#### Template Loader (`src/lib/templates/TemplateLoader.svelte`)

Umschließt Seiten-Content mit Templates basierend auf Frontmatter:

```yaml
---
template: docs,default  # Mehrere Templates (verschachtelt)
---
```

**Funktionsweise**:
- Teilt `template`-String bei Komma
- Wendet Templates rekursiv von außen nach innen an
- Jedes Template erhält `meta`-Prop und `<slot />`

#### Verfügbare Templates:

- `__layout-none.svelte` - Kein Wrapper (nur Content)
- `__layout-default.svelte` - Basis-Seiten-Layout
- `__layout-docs.svelte` - Dokumentation mit Sidebar-Menü
- `__layout-docs-contents.svelte` - Docs-Landing mit Content-Liste
- `__layout-blog.svelte` - Blog-Post-Layout

**Beispiel**:
```yaml
template: docs,default
```
Ergibt: `Default` umschließt `Docs` umschließt `Content`

### 7. Internationalisierung (i18n)

**Paraglide.js** übernimmt Multi-Language-Support.

#### Konfiguration

**Vite Plugin** (`vite.config.js`):
```javascript
paraglideVitePlugin({
  project: './project.inlang',
  outdir: './src/lib/paraglide',
  strategy: ['url', 'localStorage', "preferredLanguage", 'baseLocale'],
  urlPatterns: [
    {
      pattern: "/:path(.*)?",
      localized: [
        ["de", "/de/:path(.*)?"],
        ["en", "/en/:path(.*)?"],
      ],
    },
  ],
})
```

**Einstellungen** (`project.inlang/settings.json`):
```json
{
  "baseLocale": "de",
  "locales": ["en", "de"],
  "modules": [...]
}
```

#### Nutzung

```javascript
import { getLocale, localizeHref } from '$lib/paraglide/runtime';
import * as m from '$lib/paraglide/messages.js';

const lang = getLocale(); // 'de' oder 'en'
const href = localizeHref('/python/module', { locale: 'en' });
```

**Content-Datei-Auflösung**:
1. Prüfe URL auf Sprache (`/en/python/...`)
2. Suche nach sprachspezifischer Datei (`.en.page`)
3. Fallback auf Standard-Datei (`.page`)
4. Fallback auf andere Sprachen

### 8. Prerendering

**Static Site Generation** via `@sveltejs/adapter-static`

**Config** (`svelte.config.js`):
```javascript
adapter: adapter({
  pages: 'build',
  assets: 'build',
  fallback: '200.html',  // SPA-Fallback
  precompress: true      // Brotli-Kompression
})
```

**Globale Einstellungen** (`src/routes/+layout.js`):
```javascript
export const prerender = true;
export const trailingSlash = 'always';
```

**Funktionsweise**:
1. SvelteKit crawlt alle Routen ab `/`
2. Folgt Links in HTML, um Seiten zu entdecken
3. Führt `load`-Funktionen für jede Route aus
4. Generiert statische HTML + JSON-Dateien
5. Komprimiert mit Brotli (`.br`-Dateien)

## 🔧 Build Pipeline

### Development-Modus

```bash
npm run dev
```

**Schritte**:
1. `node prebuild/packStaticFolder/index.cjs` - Assets kopieren
2. `node prebuild/generate-subpage-files.cjs` - Sitemap generieren
3. `vite dev` - Dev-Server mit HMR starten

### Production-Build

```bash
npm run build
```

**Schritte**:
1. Pre-Build-Scripts ausführen (wie dev)
2. `vite build` - Build mit SvelteKit
   - Kompiliert Svelte-Komponenten
   - Verarbeitet MDsveX-Dateien
   - Optimiert Bilder (via `@sveltejs/enhanced-img`)
   - Bündelt und Tree-Shakes
   - Prerendert alle Routen
   - Komprimiert Assets

## 📦 Asset-Handling

### Bilder

**Markdown**:
```markdown
![Alt-Text](./image.jpg|w=800|h=600)
```

**Verarbeitung**:
1. `mdsvex-relative-images`-Plugin transformiert zu Vite-Import
2. Vites `imagetools` optimiert Bild
3. `@sveltejs/enhanced-img` generiert responsive Versionen
4. Output enthält WebP/AVIF-Formate, srcset

**Optionen**:
- `w=800` - Breite
- `h=600` - Höhe
- Wildcard: `./images/*.jpg` - Alle importieren

### Videos

Neben Content gespeichert, relativ referenziert:

```markdown
<Video src="./demo.mp4" poster="./poster.jpg" />
```

### Downloads

PDFs, ZIPs, HEX-Dateien, etc.:

```markdown
[Download](./file.hex)
```

## 🌐 URL-Struktur

### Pfad-Muster

```
/                          → index.page (Deutsch Standard)
/en/                       → index.page (Englisch)
/python/                   → content/python/index.page
/python/module/            → content/python/[...01]module/index.page
/en/python/module/         → Englische Version
```

**Trailing Slashes**: Immer enthalten (`trailingSlash: 'always'`)

### Saubere URLs

Ordering-Prefixes werden entfernt:
```
Ordner: [..01]module
URL:    /python/module/  (nicht /python/[...01]module/)
```

## 🔍 Debugging-Tipps

### Content wird nicht angezeigt

1. **Glob-Pattern prüfen** in `pageLoader.js`
2. **Frontmatter verifizieren** - `published: true`?
3. **Pre-Build-Scripts manuell ausführen**
4. **sitemap.js prüfen** - Ist Seite gelistet?

### Bilder laden nicht

1. **Relativen Pfad prüfen** - `./`-Prefix erforderlich
2. **Pack-Script ausführen** - `npm run pack`
3. **Datei in** `static_autogenerated` **verifizieren**
4. **Browser-Network-Tab** auf 404s prüfen

### Build-Fehler

1. **Pre-Build-Scripts** separat ausführen, um Probleme zu isolieren
2. **Node-Version prüfen** - 16+ erforderlich
3. **`.svelte-kit`-Cache löschen** - Ordner löschen, neu bauen
4. **Alle Imports validieren** - Keine zirkulären Abhängigkeiten

## 🚀 Neue Features hinzufügen

### Neue Content-Komponente

1. Komponente in `/src/lib/components/elements/` erstellen
2. Import zu `mdsvexplugins/mdsvex-import-components.js` hinzufügen
3. In Markdown verwenden: `<DeineKomponente prop="wert" />`

### Neues Template

1. In `/src/lib/templates/__layout-name.svelte` erstellen
2. Zu `mdsvexplugins/mdsvex-import-templates.js` hinzufügen
3. In Frontmatter verwenden: `template: name`

### Neues MDsveX-Plugin

1. Plugin in `/mdsvexplugins/dein-plugin.js` erstellen
2. `unist-util-visit`-Pattern für AST-Traversierung folgen
3. Zu `mdsvex.config.js` `remarkPlugins`-Array hinzufügen
4. Mit Beispiel-Content testen

### Neue Content-Kategorie

1. Ordner in `/src/content/neue-kategorie/` erstellen
2. `index.page` mit Frontmatter hinzufügen
3. Unterordner mit Ordering-Prefix erstellen: `[...01]erster/`
4. `npm run dev` ausführen - Sitemap wird automatisch generiert
5. Menü in Templates hinzufügen, falls nötig

## 🌟 Best Practices

### Content-Organisation
- ✅ Semantische Ordnernamen verwenden
- ✅ Assets mit Content ko-lokalisieren
- ✅ Ordering-Prefixes sparsam verwenden
- ✅ Beschreibendes Frontmatter schreiben
- ❌ Nicht zu tief verschachteln (max. 3-4 Ebenen)
- ❌ Leerzeichen in Dateinamen vermeiden

### Development-Workflow
- ✅ Pre-Build-Scripts vor Tests ausführen
- ✅ Dev und Production Builds testen
- ✅ Über Sprachen hinweg validieren
- ✅ Responsive Design prüfen
- ❌ Generierte Dateien nicht bearbeiten (`sitemap.js`, `static_autogenerated/`)
- ❌ `.svelte-kit/`-Ordner nicht committen

### Performance
- ✅ Bilder vor Hinzufügen zum Content optimieren
- ✅ Geeignete Bildformate verwenden
- ✅ Content unterhalb des Fold lazy loaden
- ✅ Externe Abhängigkeiten minimieren
- ❌ Große Videos nicht ins Repo (externes Hosting nutzen)
- ❌ Keine ganzen Icon-Bibliotheken importieren

## 🐛 Häufige Fallen

1. **Pre-Build-Scripts vergessen**
   - Symptom: Content wird nicht angezeigt, Assets 404
   - Fix: `npm run dev` ausführen (enthält Pre-Build)

2. **Falsche Bild-Pfade**
   - Symptom: Bilder laden nicht
   - Fix: Immer `./`-relative Pfade verwenden

3. **Frontmatter-Fehler**
   - Symptom: Build schlägt fehl, Seiten-Metadaten fehlen
   - Fix: YAML-Syntax validieren

4. **Zirkuläre Template-Referenzen**
   - Symptom: Stack-Overflow beim Build
   - Fix: Keine Eltern-Templates in Kindern referenzieren

5. **Sprach-Datei-Konflikte**
   - Symptom: Falsche Sprache wird angezeigt
   - Fix: `.de.page` / `.en.page`-Benennung konsistent halten

## 🎉 Fazit

Diese Architektur erreicht eine feine Balance:
- **Content-Editoren** arbeiten in vertrautem Markdown mit ko-lokalisierten Assets
- **Entwickler** haben volle Svelte/SvelteKit-Funktionalität
- **Build-System** behandelt Komplexität transparent
- **Performance** bleibt exzellent durch statische Generierung

Das Ergebnis ist eine **skalierbare, wartbare, inhaltsgetriebene Dokumentationsseite**, die weder Developer Experience noch Laufzeit-Performance opfert.

**Kernaussage**: Die Trennung wird durch eigene MDsveX-Plugins, Pre-Build-Scripts und SvelteKits flexibles Routing erreicht – nicht durch Funktionalitäts-Einschränkungen.
