# Developer Documentation: Calliope Docs Architecture

> **Target Audience**: Developers who need to understand the technical architecture of this content-driven SvelteKit application.

## 🎯 Project Philosophy

This project pushes SvelteKit to its limits to achieve **maximum separation of content from code**. Content editors work primarily in `/src/content/` with Markdown files and local assets, while developers maintain the application infrastructure. The system preserves full Svelte functionality, allowing both roles to work hand-in-hand without stepping on each other's toes.

## 🏗️ Core Architecture

### 1. Content Management System

#### Content File Structure

Content lives in `/src/content/` organized by categories:

```
src/content/
├── python/
│   ├── index.page                           # Category landing page
│   ├── [...01]module/                       # Ordered subfolder
│   │   └── index.page
│   ├── [...02]beschleunigungsmesser/       # Another ordered subfolder
│   │   ├── index.page                       # Default (German fallback)
│   │   ├── index.de.page                    # German version (optional)
│   │   ├── index.en.page                    # English version (optional)
│   │   ├── image.png                        # Co-located assets
│   │   └── demo.mp4
│   └── ...
└── tech/
    └── ...
```

**Key Conventions:**

- **File Extensions**: `.page`, `.de.page`, `.en.page`, `.svx`, `.md`
- **Ordering Prefix**: `[...01]`, `[...02]`, etc. for folder ordering (stripped from URLs)
- **Exclusion Prefix**: `!` prefix (e.g., `!index.page`) excludes from navigation/sitemap
- **Index Files**: `index.page` serves as the category/folder landing page
- **Language Files**: 
  - `index.page` = fallback version (typically German)
  - `index.de.page` = German-specific
  - `index.en.page` = English-specific
- **Assets**: Images, videos, PDFs can be placed next to content files

#### Frontmatter Schema

Every `.page` file starts with YAML frontmatter:

```yaml
---
title: Page Title                # Required: Page title
description: SEO description     # Optional: Meta description
template: docs                   # Optional: Template(s) to use (comma-separated for nesting)
published: true                  # Optional: Publish status (false = excluded)
docMenu: python                  # Optional: Which doc menu to show
docTitle: Section Title          # Optional: Doc section title
seotitle: Custom SEO Title       # Optional: Override title for SEO
tags: tag1, tag2                 # Optional: Comma-separated tags
image: ./thumbnail.jpg           # Optional: Hero/thumbnail image
---

# Page Content in Markdown
```

### 2. Routing System

#### Dynamic Route Handler

The main route is a **catch-all route**: `/src/routes/[...slugs]/+page.js`

```javascript
// Loads content based on URL slug
import { loadPage } from '$lib/scripts/pageLoader';

export async function load({ params, depends }) {
   depends("paraglide:lang");
   return await loadPage({ params });
}
```

**How it works:**

1. **Glob Import**: Uses Vite's `import.meta.glob()` to import ALL `.page` files at build time
2. **Language Resolution**: 
   - Detects language from URL (`/en/...`) or browser settings
   - Falls back to default language (German)
   - Searches for language-specific file (`.de.page`, `.en.page`)
   - Falls back to default file (`.page`)
3. **Slug Matching**: Matches URL path to file path after stripping ordering prefixes
4. **Returns**: `{ Page, meta }` - The Svelte component and its metadata

**Page Loader** (`/src/lib/scripts/pageLoader.js`):

```javascript
const allFiles = import.meta.glob(
    '$lib/../{content/**/,content}{[!!][!index]*,*/index}{,.??}.page',
    { eager: true }
);
```

This pattern:
- Matches all `.page` files in content
- Excludes files starting with `!` 
- Includes `index` files and non-index files
- Supports language suffixes (`.de`, `.en`)

#### JSON API Route

Parallel JSON API at `/src/routes/[...slugs].json/+server.js`:

- Returns page metadata and subpage list as JSON
- Used for dynamic content loading, menus, navigation
- Same language resolution logic as page loader

### 3. MDsveX Processing Pipeline

MDsveX converts Markdown to Svelte components with custom processing.

#### Configuration (`mdsvex.config.js`)

```javascript
export default {
  layout: './src/lib/mdsvex/layouts/default.svelte',
  extensions: ['.svelte.md', '.md', '.svx', '.page'],
  rehypePlugins: [
    rehypeSlug,           // Add IDs to headings
    rehypeUnwrapImages,   // Remove <p> around images
  ],
  remarkPlugins: [
    remarkFrontmatterImport,  // Import frontmatter images
    remarkRelativeImages,     // Process relative image paths
    remarkAutoloadComponents, // Auto-import components
    remarkAutoloadTemplates,  // Auto-import templates
  ]
}
```

#### Custom MDsveX Plugins (`/mdsvexplugins/`)

**1. `mdsvex-relative-images.js`**

Transforms relative image references in Markdown to Vite-compatible imports:

```markdown
![Alt text](./image.jpg|w=800)
```

Becomes:

```javascript
import img_abc123 from './image.jpg?w=800&enhanced';
```

**Features:**
- Image optimization parameters (`w=`, `h=` for width/height)
- Wildcard imports: `./images/*.jpg` imports all matching images
- EXIF metadata extraction (title, description, copyright)
- Automatic Vite imagetools integration
- PhotoSwipe gallery support

**2. `mdsvex-import-components.js`**

Auto-injects component imports into every Markdown file:

```javascript
import Svg from '$lib/components/elements/Svg.svelte';
import GitLink from '$lib/components/elements/GitLink.svelte';
import Admonition from '$lib/components/elements/Admonition.svelte';
// ... and more
```

**Usage in Markdown:**

```markdown
<Admonition type='tip'>
This is a tip!
</Admonition>

<Video src="./demo.mp4" />
```

**Available Components:**
- Layout: `Gap`, `Grid`, `Box`, `Divider`, `Zigzag`
- Media: `Svg`, `Video`, `ImageSwiper`, `YouTube`, `Vimeo`
- Docs: `Admonition`, `Steps`, `Step`, `TabbedLinks`, `UnfoldItem`
- Utility: `Button`, `GitLink`, `VersionNav`, `Versions`
- Highlighting: `V` (highlight), `Yes`, `No`

**3. `mdsvex-frontmatter-to-import.js`**

Imports images referenced in frontmatter:

```yaml
---
image: ./thumbnail.jpg
---
```

Becomes:

```javascript
import thumbnail from "./thumbnail.jpg?jpeg&w=520";
metadata.image = thumbnail;
```

**4. `mdsvex-import-templates.js`**

Replaces template stub with actual imports:

```javascript
let availTemplatesArray = {}
```

Becomes:

```javascript
import Blog from '$lib/templates/__layout-blog.svelte';
import Default from '$lib/templates/__layout-default.svelte';
// ...
let availTemplatesArray = { blog: Blog, default: Default, ... }
```

#### Custom Element Renderers (`/src/lib/mdsvex/`)

MDsveX can override default HTML element rendering:

- `img.svelte` - Enhanced image component with PhotoSwipe, EXIF metadata
- `a.svelte` - Custom link handling
- `code.svelte` - Syntax highlighting
- `video.svelte` - Video player with controls
- `table.svelte` - Styled tables

### 4. Pre-build System

Two critical scripts run before every build:

#### 1. Pack Static Folder (`prebuild/packStaticFolder/index.cjs`)

**Purpose**: Copy assets from content folders to static output with proper structure.

**Process**:
1. Scans `/src/content/` for media files (images, videos, PDFs, etc.)
2. Scans `/static/` for all files
3. Removes ordering prefixes (`[...01]` → empty string)
4. Copies to `/static_autogenerated/` with cleaned paths
5. Duplicates to language-specific folders (`/en/`, `/de/`)

**Why?**: Assets next to content files need to be accessible at runtime, and SvelteKit only serves from `/static`. This script bridges the gap.

**Example**:
```
src/content/python/[...02]beschleunigungsmesser/image.jpg
    → static_autogenerated/python/beschleunigungsmesser/image.jpg
    → static_autogenerated/de/python/beschleunigungsmesser/image.jpg
    → static_autogenerated/en/python/beschleunigungsmesser/image.jpg
```

#### 2. Generate Sitemap (`prebuild/generate-subpage-files.cjs`)

**Purpose**: Pre-build a navigation/sitemap structure from content files.

**Process**:
1. Scans all `.page` files in `/src/content/`
2. Reads frontmatter metadata
3. Builds hierarchical structure by content type and language
4. Generates `/src/sitemap.js` with helper functions

**Output Structure** (`src/sitemap.js`):

```javascript
const sitemap = {
  "de": {
    "python": {
      mainCategories: [...],  // Top-level categories
      paths: {                // All paths with metadata and subpages
        "python/module": {
          slug: "python/module",
          title: "Module",
          description: "...",
          subpages: [...]
        }
      }
    },
    "tech": { ... }
  },
  "en": { ... }
}
```

**Helper Functions**:
```javascript
getContentTypes(lang)           // ['python', 'tech']
getCategories(contentType, lang) // Main categories
getSubpages(path, lang)         // Child pages
getPage(path, lang)             // Single page metadata
```

**Used by**:
- Navigation menus (`DocsMenu.svelte`)
- Breadcrumbs
- Prev/Next navigation
- Sitemap generation

### 5. Template System

**Multi-layered template system** for flexible layouts.

#### Template Loader (`src/lib/templates/TemplateLoader.svelte`)

Wraps page content in templates based on frontmatter:

```yaml
---
template: docs,default  # Multiple templates (nested)
---
```

**How it works**:
- Splits `template` string by comma
- Recursively applies templates from outside-in
- Each template receives `meta` prop and `<slot />`

#### Available Templates:

- `__layout-none.svelte` - No wrapper (just content)
- `__layout-default.svelte` - Basic page layout
- `__layout-docs.svelte` - Documentation with sidebar menu
- `__layout-docs-contents.svelte` - Docs landing with content list
- `__layout-blog.svelte` - Blog post layout

**Example**:
```yaml
template: docs,default
```
Results in: `Default` wraps `Docs` wraps `Content`

### 6. Internationalization (i18n)

**Paraglide.js** handles multi-language support.

#### Configuration

**Vite Plugin** (`vite.config.js`):
```javascript
paraglideVitePlugin({
  project: './project.inlang',
  outdir: './src/lib/paraglide',
  strategy: ['url', 'localStorage', "preferredLanguage", 'baseLocale'],
  urlPatterns: [
    {
      pattern: "/:path(.*)?",
      localized: [
        ["de", "/de/:path(.*)?"],
        ["en", "/en/:path(.*)?"],
      ],
    },
  ],
})
```

**Settings** (`project.inlang/settings.json`):
```json
{
  "baseLocale": "de",
  "locales": ["en", "de"],
  "modules": [...]
}
```

#### Usage

```javascript
import { getLocale, localizeHref } from '$lib/paraglide/runtime';
import * as m from '$lib/paraglide/messages.js';

const lang = getLocale(); // 'de' or 'en'
const href = localizeHref('/python/module', { locale: 'en' });
```

**Content File Resolution**:
1. Check URL for language (`/en/python/...`)
2. Look for language-specific file (`.en.page`)
3. Fall back to default file (`.page`)
4. Fall back to other languages

### 7. Prerendering

**Static Site Generation** via `@sveltejs/adapter-static`

**Config** (`svelte.config.js`):
```javascript
adapter: adapter({
  pages: 'build',
  assets: 'build',
  fallback: '200.html',  // SPA fallback
  precompress: true      // Brotli compression
})
```

**Global Settings** (`src/routes/+layout.js`):
```javascript
export const prerender = true;
export const trailingSlash = 'always';
```

**How it works**:
1. SvelteKit crawls all routes starting from `/`
2. Follows links in HTML to discover pages
3. Executes `load` functions for each route
4. Generates static HTML + JSON files
5. Compresses with Brotli (`.br` files)

**Output**:
```
build/
├── python/
│   ├── module/
│   │   ├── index.html
│   │   ├── index.json
│   │   └── *.br (compressed)
├── en/
│   └── python/
│       └── ...
└── _app/
    └── immutable/
```

## 🔧 Build Pipeline

### Development Mode

```bash
npm run dev
```

**Steps**:
1. `node prebuild/packStaticFolder/index.cjs` - Copy assets
2. `node prebuild/generate-subpage-files.cjs` - Generate sitemap
3. `vite dev` - Start dev server with HMR

### Production Build

```bash
npm run build
```

**Steps**:
1. Run pre-build scripts (same as dev)
2. `vite build` - Build with SvelteKit
   - Compiles Svelte components
   - Processes MDsveX files
   - Optimizes images (via `@sveltejs/enhanced-img`)
   - Bundles and tree-shakes
   - Prerenders all routes
   - Compresses assets

### Deployment

```bash
npm run deploy
```

**Additional steps**:
- Generates `sitemap.xml` via `super-sitemap`
- Can deploy to Cloudflare Pages, Vercel, or static hosting

## 📦 Asset Handling

### Images

**Markdown**:
```markdown
![Alt text](./image.jpg|w=800|h=600)
```

**Processing**:
1. `mdsvex-relative-images` plugin transforms to Vite import
2. Vite's `imagetools` optimizes image
3. `@sveltejs/enhanced-img` generates responsive versions
4. Output includes WebP/AVIF formats, srcset

**Options**:
- `w=800` - Width
- `h=600` - Height
- Wildcard: `./images/*.jpg` - Import all

### Videos

Stored next to content, referenced relatively:

```markdown
<Video src="./demo.mp4" poster="./poster.jpg" />
```

### Downloads

PDFs, ZIPs, HEX files, etc.:

```markdown
[Download](./file.hex)
```

**Vite Config** allows these extensions:
```javascript
assetsInclude: ['**/*.hex', '**/*.xml', '**/*.pdf', '**/*.uf2', '**/*.zip']
```

### Path Patterns

```
/                          → index.page (German default)
/en/                       → index.page (English)
/python/                   → content/python/index.page
/python/module/            → content/python/[...01]module/index.page

Ordering prefixes are stripped:
```
Folder: [..01]module
URL:    /python/module/  (not /python/[...01]module/)

## 🔍 Debugging Tips

### Content Not Showing

1. **Check glob pattern** in `pageLoader.js`
2. **Verify frontmatter** - `published: true`?
3. **Run pre-build scripts** manually
4. **Check sitemap.js** - Is page listed?

### Images Not Loading

1. **Check relative path** - `./` prefix required
2. **Run pack script** - `npm run pack`
3. **Verify file in** `static_autogenerated`
4. **Check browser network tab** for 404s

### MDsveX Plugin Not Working

1. **Order matters** in `mdsvex.config.js` `remarkPlugins` array
2. **Check plugin output** - Add `console.log` to plugin
3. **Verify regex patterns** - Test with [regex101.com](https://regex101.com)

### Routing Issues

1. **Check URL pattern** in browser
2. **Verify slug matching** in `slugFromPath()` function
3. **Test language resolution** - Try `/en/` prefix
4. **Check catch-all route** - `[...slugs]` exists?

### Build Errors

1. **Run pre-build scripts** separately to isolate issues
2. **Check Node version** - 16+ required
3. **Clear `.svelte-kit` cache** - Delete folder, rebuild
4. **Validate all imports** - No circular dependencies

## 🚀 Adding New Features

### New Content Component

1. Create component in `/src/lib/components/elements/`
2. Add import to `mdsvexplugins/mdsvex-import-components.js`
3. Use in Markdown: `<YourComponent prop="value" />`

### New Template

1. Create in `/src/lib/templates/__layout-name.svelte`
2. Add to `mdsvexplugins/mdsvex-import-templates.js`
3. Use in frontmatter: `template: name`

### New MDsveX Plugin

1. Create plugin in `/mdsvexplugins/your-plugin.js`
2. Follow `unist-util-visit` pattern for AST traversal
3. Add to `mdsvex.config.js` `remarkPlugins` array
4. Test with sample content

### New Content Category

1. Create folder in `/src/content/new-category/`
2. Add `index.page` with frontmatter
3. Create subfolders with ordering prefix: `[...01]first/`
4. Run `npm run dev` - sitemap auto-generates
5. Add menu in templates if needed

## 🐛 Common Pitfalls

1. **Forgetting Pre-build Scripts**
   - Symptom: Content not showing, assets 404
   - Fix: Run `npm run dev` (includes pre-build)

2. **Wrong Image Paths**
   - Symptom: Images don't load
   - Fix: Always use `./` relative paths

3. **Frontmatter Errors**
   - Symptom: Build fails, page metadata missing
   - Fix: Validate YAML syntax

4. **Circular Template References**
   - Symptom: Stack overflow at build
   - Fix: Don't reference parent templates in children

5. **Language File Conflicts**
   - Symptom: Wrong language shows
   - Fix: Ensure `.de.page` / `.en.page` naming is consistent
